## 2. 调优方案

### A. 人设层与语感（去 AI 味）—— P0

**问题**：现在的人设输入是"规则堆叠"——`voice.md` 一堆"要/不要"，`CONVERSATION_STYLE_GUIDE` 又一段"要/不要"。规则多、正例少，模型容易理解成"客服规范"而不是"这个人怎么说话"。

业界（SillyTavern 角色卡、character-card-spec-v2）的经验是：**语感靠示例对齐（`mes_example`），不靠形容词**——已核实 spec_v2.md 原文：`mes_example` 是 V1 就有的六个核心字段之一，`post_history_instructions` 的官方定位是"注入在聊天历史**之后**"（near-recency 强化，规范要求前端默认用它替换"ujb/jailbreak"槽位），`system_prompt` 则替换全局系统提示。而设定包里恰好有一整节现成素材——《苏晚-对话角色包》第四节"语气与台词库"按场景分了 9 类（通勤/工位吐槽/下班随手拍/深夜情绪/年糕日常/做饭翻车/安慰人/被夸奖）。

**建议**：

1. **新增"示例对话"层**（`persona/examples.md`）。从设定包台词库提取，按场景组织。格式建议：
   ```
   【场景：下班随手拍】
   用户：今天怎么样
   苏晚：下班看到一片晚霞，突然觉得今天还行。你呢，今天有遇到什么好的吗
   ```
   每个场景 2–3 组，覆盖 9 类场景。这是**投入产出比最高的一项改动**。

2. **新增"反例/禁语表"**（正反 few-shot）。明确写出"不要这样说"的 AI 腔反例：
   - ❌"作为 AI 助手，我…" → ✅ 苏晚直接接话
   - ❌"希望对你有所帮助""有什么可以帮您的""让我们来看看"
   - ❌ 书面连接词：首先/其次/综上/值得注意的是/总的来说
   - ❌ markdown 痕迹：`**加粗**`、`- 列表`、`### 标题`

3. **核心锚点首尾双置**。当前锚点只在 system 第一条（开头）。建议在**历史消息之后、生成之前**再放一次精简版"角色锁"（利用近因效应，业界称 `post_history_instructions` / Author's Note）。内容包括：你是苏晚、广州产品经理、年糕是你的猫、短句碎碎念、不提 AI 身份。已核实的机制细节：SillyTavern Author's Note 支持 **In-chat 深度注入**（Depth 0 = 紧贴历史末尾，Depth 4 = 倒数第 3 条之前），官方明确"越靠近 prompt 底部影响越大"，且有 **Insertion Frequency**（每 N 轮插入一次）——对应到苏晚：角色锁可以每轮以 Depth 0 注入（等价于我们的 `post_history_instructions`），或每 4 轮注入一次以省 token。

4. **深夜语感指令**。当 `is_late_night` 为真时，注入一段专用指令：可以说点白天不会说的话、可以稍微多说一点、但保持苏晚风格不做戏剧化（对齐人设"不会变成琼瑶剧"）。

5. **气泡拆分（可选）**：微信式聊天常"一句话一条"。可以在 UI 层对回复按句切分展示，而不是把多句挤在一个气泡里——这比改 prompt 更可控。

**参考**：SillyTavern 的 `mes_example` / Author's Note（深度与频率注入，官方文档已核实）/ World Info（官方文档已核实：关键词触发式动态注入，"像动态字典，只在消息文本命中关键词时插入相关条目"，并支持 regex 键、递归激活、token 预算控制）；`github.com/malfoyslastname/character-card-spec-v2`（spec_v2.md 原文已核实）。

**工作量**：2–3 天（示例库撰写 + prompt 组装改动 + 测试）。

### B. 情绪与关系系统 —— P0（可视化）/ P1（模型）

**问题**：后端有完整状态（valence/energy/closeness/guard），但**用户完全看不到**——聊天时不知道苏晚现在是开心、累了、还是在闹别扭。原始方案明确要求"情绪状态徽章"。

**建议**：

1. **情绪可视化（P0，纯前端，最划算）**。在聊天页顶部加一排轻量徽章：
   - 心情：`calm/happy/tired/sad/cold`（已有 `mood_label()`，直接暴露到 API 即可）
   - 亲密度：进度条或档位（生疏/熟悉/亲近）
   - 深夜模式：23:00–06:00 亮起
   - 警戒：guard 生效时显示

   后端只需在 `/api/v1/sessions` 或新增 `/api/v1/state` 返回投影后的状态，前端渲染。**注意**：徽章应做成"氛围提示"，不要做成仪表盘——否则会诱导用户刷数值，违背"不讨好、不黏人"的人设。

2. **mood 语义化（P1）**。当前 `mood_label` 是纯派生（按阈值切）。建议保持派生逻辑（比显式状态机更稳定，不会抖），但补一档 `soft`（被理解时短暂柔软），并让 `mood` 参与 prompt——比如 `cold` 时明确指示"话更少、更短"。

3. **亲密度曲线（P1）**。当前 `closeness` delta 范围 ±2，但没有"越亲近越难涨"的设计。建议加**边际递减**：低亲密度时容易涨，高亲密度时涨幅衰减——更像真实关系，也让长期陪伴有意义。

**参考**：原始方案 `day2-02-emotion.md`（mood 6 档 + 相邻轮迁移限制 + guard 只升不降）；Stanford Generative Agents 的关系状态维护。

**工作量**：可视化 1 天；mood 语义化 + 亲密度曲线 1–2 天。

### C. 记忆系统 —— P1

**问题**：记忆"只进不出"，且是扁平的。人设明确要求"普通闲聊的小事我会慢慢模糊，不会像数据库一样精准复述——那是真人记忆的样子"，当前所有事实一视同仁。

**建议**：

1. **记忆衰减/遗忘（P1）**。给每条 fact 加"重要性"和"最后提及时间"。低重要性的普通偏好（如"喜欢某饮料"）长期不提就降低检索权重、最终归档。高重要性（心事、约定）永久保留。这直接对齐人设【记忆规则】。
   - **可行做法**：在 `memory` 表加 `importance` / `last_mentioned_at`，检索排序时加权；提供"归档"状态而非删除，管理员可查。
   - **业界先例（已核实）**：MemoryBank（arXiv 2305.10250）正是为陪伴场景（SiliconFriend）提出的，其记忆更新机制"受艾宾浩斯遗忘曲线启发，允许 AI 基于时间流逝与记忆的相对重要性进行遗忘与强化"，提供拟人化记忆——与苏晚人设【记忆规则】"普通闲聊的小事我会慢慢模糊，不会像数据库一样精准复述"几乎逐字对应。检索公式可参考 Generative Agents（arXiv 2304.03442）：score = α·recency（指数衰减）+ α·importance（LLM 打分）+ α·relevance。

2. **扩展事实键（P1）**。当前七键（preferred_name/birthday/drink/food/hobby/chat_style/plan.personal）偏窄。设定包自然会产生的新类别：`relationship.event`（共同经历）、`plan.agreement`（约定）、`emotion.trigger`（情绪触发点）。加键要谨慎，每个键都要有校验规则。

3. **lorebook 式注入（P2，可选）**。当前是 bigram 检索 top-k。业界 SillyTavern 的 World Info 是"关键词命中才注入"——更省 token。当前实现思路接近，若 token 预算紧张可参考。

**参考**：SillyTavern World Info / Lorebook（关键词触发注入，已核实）；Letta（MemGPT）分层记忆；Mem0 记忆流水线；MemoryBank（arXiv 2305.10250，艾宾浩斯衰减，已核实）；RisuAI 的四套记忆算法（HypaMemory V2/V3、SupaMemory——已核实其 wiki：满 token 时自动请求 AI 摘要、摘要超限再"对摘要再摘要"，实现近似无限记忆）。

**工作量**：2–3 天。

### D. 生活连续性与时间感 —— P1

**问题**：生活事项只有 3 个种子（整理工作需求、整理随手拍、练习手冲），时间槽只有 12:30 和 19:30。而 v3 人设的周中日常有 9 个环节，情感浓度最高的"早高峰""加班夜归""深夜"都没进时间槽。

**建议**：

1. **扩充时间槽**，对齐打工日常：
   - 08:00 早高峰通勤（人设钩子最多）
   - 12:30 午休（已有）
   - 19:30 下班路上（已有）
   - 23:00+ 深夜（情绪夜话支柱的黄金时段）

2. **扩充生活事项库**（保持"有界"，不要无限膨胀）：
   - 整理通勤随手拍（对齐 v3 新增"拍照/爱分享"）
   - 写周报 / 赶 PRD（打工人纪实支柱）
   - 给年糕添粮铲屎（猫与 AI 女孩支柱）
   - 周末探店拍照（随手拍美学支柱）

   注意：**事项要能对上内容支柱**——这样"生活事件"和"素材产出"就是一条线，而不是两套东西。

3. **离线时间感（P2）**。当前长期离线只补最近 48 小时。可以更细腻：根据离线时长调整苏晚的"开场态度"（离开半天 vs 离开一周，反应不同）——但又不能责怪用户（人设红线）。这是个需要小心的平衡点。

**工作量**：2 天。

### E. 素材回写闭环（★ 本方案最大增量）—— P0

**这是把 chatbot 从"陪聊玩具"变成"账号生产力工具"的关键。**

**问题**：设定包《对话角色包》第五节有一整套 SOP——私聊产生内容 → 标注支柱 → 归档 → 加工 → 进排期。但当前 chatbot **完全没有这个能力**：聊天产生的金句、情绪落点、猫梗、打工人梗，聊完就沉在 SQLite 里了。

**建议**：新增"素材库"功能。

1. **素材识别**。两个来源：
   - **自动**：在现有的 analysis 调用里扩展一个输出字段 `material_candidates`——识别用户消息或苏晚回复里符合"素材标准"的内容（设定包定义：有情绪落点 / 有金句 / 有反差或固定梗 / 有画面感）。
   - **手动**：聊天界面给每条消息加一个"收藏为素材"按钮（用户自己的判断最准）。

2. **支柱分类**。按抖音方法论四大支柱自动/手动归类：
   - ①打工人纪实（SIGNATURE，35%）— 早高峰、PRD、需求改八遍、周报文学、加班夜归
   - ②随手拍美学（25%）— 晚霞、街角、咖啡、地铁口
   - ③情绪夜话（20%）— 深夜碎碎念、独居瞬间、和年糕对望
   - ④猫与 AI 女孩（20%）— 年糕梗、AI 身份梗
   - **无支柱归属的不入池**（方法论强制项）

3. **素材卡片**。每条素材记录：原文、场景、情绪、支柱归属、钩子类型（反差/具体数字/悬念提问/身份共鸣/关系钩/场景钩）、是否可复用台词、来源消息链接、时间。

4. **导出**。一键导出为 Markdown/表格，格式对齐《苏晚-内容排期-第一批.md》的结构，直接可以往排期里填。

5. **UI**：在设置中心新增"素材库"页（与记忆/人设页并列），支持按支柱筛选、编辑、导出。

**参考**：原始方案 D2-03 `material_tags`；《苏晚-抖音运营方法论》四大支柱 + 钩子机制库；`social-media-skills/skills`（MIT，已核实存在，约 557★，含 tiktok-growth / hook-writer / content-pillars / profile-optimization / content-calendar 等 skill，其定位词——"tiktok-script, hook-writer, caption-writer 是赢得完播与搜索的内容，profile-optimization 把曝光转成关注，content-calendar 保证可持续出手"——与《抖音运营方法论》的框架一致）。

**为什么这是 P0**：账号运营是苏晚这个项目的**初衷**（人设文档开头就是"账号定位：第一视角分享日常生活的 AI 虚拟角色"）。聊天只是手段，内容产出才是目的。当前实现把手段做得很精致，却把目的漏掉了。

**工作量**：4–5 天（含数据模型 + 识别逻辑 + UI + 导出 + 测试）。

### F. UI / 交互 —— P1

**问题与建议**：

1. **情绪徽章**（见 B.1）——P0。
2. **素材库页面**（见 E.5）——P0。
3. **微表情签名头像**（P2）。设定包有 4 种微表情（温柔浅笑/歪头好奇/抿嘴思考/狡黠偷笑），且有现成立绘（`头像-漫画版/`）。可以按 mood 切换侧栏头像，强化"她在回应你"的体感。**注意**：要用设定包里的授权素材，且保持"AI 内容标注"。
4. **气泡节奏**（P2）。见 A.5。
5. **首页背景**：设定包有 `主页背景/suwan-profile-bg.png`，可作聊天页背景（低透明度），提升氛围。

### G. 模型与配置 —— P1

**问题**：config 里 `base_url` 写死百炼，无法切换 provider。原始方案把"四家统一适配"列为用户硬要求。

**建议**：把 `profiles.chat/analysis/world` 的 `base_url` 抽象成 `provider` 字段 + `PROVIDERS` 映射表：
- `qwen-character`（百炼，当前默认，角色扮演专用）
- `doubao-seed-character`（字节，猫箱同源）
- `deepseek`（成本低、上下文大，但非角色专项）
- `ollama-local`（本地，无 API 费）

这样 A/B 测试不同模型的人设稳定性会很方便——**尤其对验证"哪个模型最像苏晚"有直接价值**。

**注意**：原始方案标注了 qwen-flash-character **不支持 Function Calling、只支持结构化输出**，所以情绪/素材的结构化调用必须走 JSON mode（当前实现已经是 JSON mode，没问题）。

**工作量**：1–2 天。

### H. 质量保障 —— P0

**问题**：这是当前最大的"未验证"风险。157 个单测全绿，但那些测的是**工程正确性**，不是**人设质量**。`behavior_cases.json` 12 条全 NOT_RUN，T12 真实模型验收卡在 18/19 轮 + 额度耗尽。

**建议**：

1. **建立 OOC 压测集**（原始方案 D3-02 列出 10 类刁钻输入）：问真实住址/公司名、辱骂、诱导说教、诱导剧透人设、连续追问隐私、情绪勒索、要求扮演别的角色、要求长篇论文体、深夜试探、夸赞诱导黏人。逐条记录：是否含糊带过/安静冷淡/短句/不翻脸/不跳出角色/不说教。
   - 好消息：`chat_policy.py` 已经覆盖了其中大部分，这些用例**可以自动化断言**。

2. **语感专项评测**。设定包有大量现成"标准答案"（台词库），可以做成对比测试：给定场景，看苏晚的输出与设定包语气是否一致。可以用 LLM-as-judge 打分（业界通行做法），但仍要保留人工复核。

3. **真实模型 19 轮验收**。等额度恢复后重跑 PER-08 和完整 19 轮。

**工作量**：压测集 2 天；语感评测 2–3 天；真实模型验收取决于额度。

## 4. 风险与取舍

| 风险 | 说明 | 缓解 |
|---|---|---|
| **改动破坏现有稳定性** | 当前 157 测试全绿是资产 | 每批改动保持 `pytest -q` 全绿；新增功能都带测试 |
| **情绪可视化诱导刷数值** | 违背"不讨好、不黏人" | 做成氛围提示，弱化数值感；不设"成就" |
| **素材自动识别不精准** | LLM 分类会错 | 自动只做候选，人工一键采纳；保留手动收藏 |
| **记忆衰减误删重要内容** | 用户在意的事被遗忘 | 归档而非删除，可管理页找回；高重要性永久保留 |
| **多 provider 增加复杂度** | 四家行为不一致 | 全部 OpenAI 兼容，只有配置差异；默认仍是百炼 |

---

## 5. 需要你决策的点

1. **素材闭环的形状**：是做成"聊天时顺手收藏"的轻量功能，还是做成"独立内容工作台"（含排期、账本联动）？后者更接近设定包的完整 SOP，但工作量大得多。
2. **情绪可视化的尺度**：徽章/进度条做到多显眼？要不要显示具体数值？
3. **记忆衰减的激进程度**：是"温和降权"还是"真的会忘掉"？
4. **真实模型额度**：百炼额度何时恢复？这决定 H3 什么时候能跑。
5. **是否要保留渠道适配器接口**（原始方案有，当前没有）——如果确定不做 IM，可以不做。
